TP1 : Introduction à la blockchain

Objectifs

  • Découvrir l'architecture réseau pair à pair (P2P) et la blockchain comme exemple de réseau P2P.
  • Connaître les types de réseaux déployables avec un client blockchain (public ou privé/consortium, consensus).
  • Connaître les moyens de se connecter à un réseau existant ou d'en déployer un (client, Docker, VM, cloud, BaaS).
  • Déployer son propre réseau privé avec le client Hyperledger Besu.
  • Se familiariser avec les outils de développement (smart contracts, Web3, Remix, Hardhat, Truffle).

Questions

Question 1 : architecture

Lisez la documentation de Besu pour comprendre sa structure et ses composants. Décrivez le fonctionnement de la blockchain à l'aide d'un schéma simplifié d'architecture réseau P2P.

Question 2 : installation d'un nœud

Installez Besu localement (distribution binaire ou image Docker) et lancez un nœud. Confirmez qu'il fonctionne : consultez le journal et interrogez-le avec curl (API JSON-RPC activée).

curl -X POST -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"web3_clientVersion","params":[],"id":1}' \
  http://127.0.0.1:8545
Conseil : Besu fonctionne sous Windows mais avec des difficultés possibles. Utilisez de préférence une machine ou une VM Linux (Ubuntu).

Question 3 : réseau privé QBFT à 4 nœuds

Lancez localement un réseau privé de 4 nœuds avec le consensus QBFT, en suivant le tutoriel Besu (version 23.4.0). Vérifiez que les blocs sont produits et que les nœuds sont connectés (eth_blockNumber, net_peerCount).

Le tutoriel est lié à une version précise de Besu. Si vous utilisez une version plus récente, consultez la documentation de cette version : certaines options de ligne de commande ou de configuration ont pu changer.

Question 4 : types de transactions

À partir de la documentation, identifiez les types de transactions que l'on peut envoyer sur un réseau blockchain (par usage : transfert, déploiement de contrat, appel de contrat ; et par format de transaction).

Question 5 : premier smart contract

Lisez la documentation sur les smart contracts. Compilez, déployez et testez le contrat Storage.sol ci-dessous (Solidity), qui stocke puis restitue une valeur.

// SPDX-License-Identifier: GPL-3.0
pragma solidity >=0.8.2 <0.9.0;

/// @title Storage
/// @dev Stocke et restitue une valeur dans une variable
contract Storage {
    uint256 number;

    /// @param num valeur à stocker
    function store(uint256 num) public {
        number = num;
    }

    /// @return valeur de `number`
    function retrieve() public view returns (uint256) {
        return number;
    }
}

Dans Remix, déployez et utilisez le contrat : d'abord avec la machine virtuelle intégrée, puis sur votre réseau privé via un réseau injecté par MetaMask (chain ID de votre fichier genesis).

Question 6 : première DApp avec Hardhat

Suivez le tutoriel de démarrage Hardhat (contrat Lock.sol). Adaptez hardhat.config.js pour déployer et tester la DApp sur votre réseau privé Besu. Voir le TP2 pour une configuration type.
