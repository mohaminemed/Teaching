Tutoriel : développement d'une DApp NFT avec Hardhat et IPFS

Ce tutoriel sert de point de départ pour la question 3 du TP2. Il est volontairement minimal : à vous de le compléter (galerie, transfert, tests).

Prérequis

  • Node.js (version LTS) et npm.
  • MetaMask installé dans le navigateur.
  • Un nœud IPFS local : Kubo (commande ipfs).

1. Initialisation du projet

mkdir nft-dapp && cd nft-dapp
npm init -y
npm install --save-dev hardhat@^2 @nomicfoundation/hardhat-toolbox@^5 dotenv
npm install @openzeppelin/contracts@4.9.6
npx hardhat init        # choisir "Create a JavaScript project"

2. Contrat intelligent ERC-721

Créez contracts/MyNFT.sol. Le contrat utilise ERC721URIStorage afin d'associer à chaque NFT une URI (ici un lien IPFS) : sans URI, le NFT ne pointerait vers aucun contenu.

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract MyNFT is ERC721URIStorage, Ownable {
    uint256 public tokenCounter;

    constructor() ERC721("MyNFT", "MNFT") {}

    /// @notice Crée un NFT pour `recipient`, dont les métadonnées sont à `uri` (ex. ipfs://<CID>)
    function createNFT(address recipient, string memory uri) public onlyOwner returns (uint256) {
        uint256 newTokenId = tokenCounter;
        tokenCounter++;
        _safeMint(recipient, newTokenId);
        _setTokenURI(newTokenId, uri);
        return newTokenId;
    }
}
Ce code correspond à OpenZeppelin 4.x. En version 5, le constructeur de Ownable prend un argument (Ownable(msg.sender)) et la version minimale de Solidity est 0.8.20.

3. Configuration de Hardhat

require("dotenv").config();
require("@nomicfoundation/hardhat-toolbox");

module.exports = {
  solidity: {
    version: "0.8.24",
    // "paris" évite l'opcode PUSH0 (non supporté par un réseau Besu dont le genesis n'active pas Shanghai)
    settings: { evmVersion: "paris" },
  },
  networks: {
    localhost: { url: "http://127.0.0.1:8545" },          // npx hardhat node
    besu: {
      url: "http://127.0.0.1:8545",                       // RPC d'un de vos nœuds Besu
      accounts: process.env.PRIVATE_KEY ? [process.env.PRIVATE_KEY] : [],
    },
  },
};

Créez un fichier .env contenant PRIVATE_KEY=0x... (clé d'un compte de test pré-financé de votre réseau Besu) et ajoutez .env à .gitignore. Ne publiez jamais une clé privée.

4. Déploiement

const { ethers } = require("hardhat");

async function main() {
  const myNFT = await ethers.deployContract("MyNFT");
  await myNFT.waitForDeployment();
  console.log("MyNFT déployé à :", await myNFT.getAddress());
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
# Réseau local Hardhat (développement)
npx hardhat node
npx hardhat run scripts/deploy.js --network localhost

# Réseau privé Besu (TP1)
npx hardhat run scripts/deploy.js --network besu

5. Stockage décentralisé avec IPFS

La bibliothèque js-ipfs utilisée dans les anciennes versions de ce tutoriel n'est plus maintenue. Utilisez un démon Kubo local et le client kubo-rpc-client :

ipfs init
ipfs config --json API.HTTPHeaders.Access-Control-Allow-Origin '["http://localhost:5173"]'
ipfs config --json API.HTTPHeaders.Access-Control-Allow-Methods '["PUT","POST"]'
ipfs daemon

Les deux lignes config autorisent l'interface web (CORS) à appeler l'API IPFS locale (port 5001).

6. Interface web

npm create vite@latest frontend -- --template react
cd frontend
npm install
npm install web3 kubo-rpc-client
npm run dev          # http://localhost:5173

Copiez l'ABI du contrat (champ abi du fichier artifacts/contracts/MyNFT.sol/MyNFT.json) dans frontend/src/MyNFT.abi.json, puis remplacez le contenu de src/App.jsx :

import { useState } from "react";
import Web3 from "web3";
import { create } from "kubo-rpc-client";
import abi from "./MyNFT.abi.json";

const CONTRACT_ADDRESS = "ADRESSE_DU_CONTRAT";
const ipfs = create({ url: "http://127.0.0.1:5001" });

export default function App() {
  const [file, setFile] = useState(null);
  const [status, setStatus] = useState("");

  const mintNFT = async () => {
    try {
      const [account] = await window.ethereum.request({ method: "eth_requestAccounts" });
      const web3 = new Web3(window.ethereum);
      const { cid } = await ipfs.add(file);                       // 1. fichier sur IPFS
      const contract = new web3.eth.Contract(abi, CONTRACT_ADDRESS);
      await contract.methods.createNFT(account, `ipfs://${cid}`)  // 2. transaction on-chain
        .send({ from: account });
      setStatus("NFT créé : ipfs://" + cid);
    } catch (e) {
      setStatus("Erreur : " + e.message);
    }
  };

  return (
    <div>
      <h1>Créer un NFT</h1>
      <input type="file" onChange={(e) => setFile(e.target.files[0])} />
      <button onClick={mintNFT} disabled={!file}>Créer le NFT</button>
      <p>{status}</p>
    </div>
  );
}

7. Test

Ouvrez l'interface, connectez MetaMask au réseau choisi (chain ID de votre réseau), puis créez un NFT. Comme createNFT est réservé au propriétaire (onlyOwner), la transaction doit être envoyée depuis le compte qui a déployé le contrat.

Pour aller plus loin

  • Faire pointer l'URI vers un fichier JSON de métadonnées (name, description, image) plutôt que directement vers l'image.
  • Permettre à tout utilisateur de créer des NFT (et réfléchir aux conséquences).
  • Écrire des tests Hardhat (création, droits, transfert).
